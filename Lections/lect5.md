# Конспект лекции №5
## Обработка и интерпретация сигналов
### Тема: Минимальная спэновая форма (MSF). Построение минимальной решётки (trellis) линейного кода. Алгоритм Витерби

---

## 1. Решётчатое представление линейных кодов

Решётка (trellis) — это способ визуализации всех кодовых слов линейного блочного кода в виде ориентированного графа с ярусами. Каждый путь в этом графе от начального до конечного узла соответствует одному конкретному кодовому слову.

### Зачем нужна решётка?

Решётка позволяет решить главную проблему декодирования — экспоненциальный рост числа вариантов при увеличении длины кода. Вместо перебора всех 2^k кодовых слов мы используем динамическое программирование, которое эффективно отсеивает заведомо неперспективные пути.

Основные применения решёток:
- декодирование по максимуму правдоподобия (алгоритм Витерби);
- мягкое декодирование с использованием вероятностных метрик из канала;
- анализ структуры кода без полного перебора;
- понимание сложности декодирования через профиль состояний.

### Структура решётки

Решётка имеет следующие элементы:
- уровни (ярусы) от 0 до n, где n — длина кода;
- вершины (узлы) на каждом ярусе — это состояния, соответствующие текущему "накопленному" информационному вектору;
- рёбра, соединяющие вершины соседних ярусов, помеченные кодовым символом (0 или 1);
- путь от яруса 0 до яруса n задаёт конкретное кодовое слово.

Количество вершин на разных ярусах может меняться. В минимальной решётке это число минимально возможное для данного кода.

## 2. Минимальная спэновая форма порождающей матрицы

Чтобы построить решётку с наименьшим числом узлов, порождающую матрицу G необходимо привести к специальному виду — минимальной спэновой форме (MSF, Minimal Span Form).

### Ключевые понятия

Для каждой строки матрицы G (соответствующей одному базисному вектору кода) определяются:
- начало строки L_i — номер столбца, где стоит первый ненулевой элемент;
- конец строки R_i — номер столбца, где стоит последний ненулевой элемент;
- интервал строки — отрезок [L_i, R_i];
- активные элементы строки — все элементы от L_i до R_i включительно.

### Условия минимальной спэновой формы

Матрица G находится в MSF, если выполняются два условия:
1. все начала строк L_i различны;
2. все концы строк R_i различны.

Это означает, что каждая строка имеет уникальную позицию первого и последнего ненулевого элемента.

### Алгоритм приведения к MSF

Процесс приведения состоит из следующих шагов:

1. Привести матрицу G к систематическому виду (если это ещё не сделано) с помощью элементарных операций над строками и перестановок столбцов.

2. Для каждой строки определить L_i и R_i.

3. Выполнять сложение строк (XOR) для устранения "конфликтов" — ситуаций, когда две строки имеют одинаковые L_i или одинаковые R_i. Сложение строк не меняет линейное пространство кода.

4. После устранения всех конфликтов упорядочить строки по возрастанию L_i.

5. Проверить, что все L_i и R_i различны. Если нет — повторить шаг 3.

### Пример приведения к MSF

Рассмотрим исходную матрицу G размера 3×6:

G =
1 1 0 1 0 0
0 1 1 0 1 0
0 0 1 1 1 1

Проверим начала и концы строк:
- строка 1: L₁=1, R₁=4
- строка 2: L₂=2, R₂=5
- строка 3: L₃=3, R₃=6

Все L различны (1,2,3), все R различны (4,5,6). Это уже MSF.

### Значение MSF

Минимальная спэновая форма важна потому, что количество узлов в решётке на каждом ярусе определяется числом активных строк — тех, чей интервал покрывает данный столбец. Чем меньше вариация числа активных строк, тем компактнее решётка.

## 3. Построение минимальной решётки

Имея матрицу G в MSF, можно построить решётку по ярусам.

### Определение активных строк

Для каждого столбца i (i от 1 до n) определяем множество активных строк — тех, для которых выполняется условие L_j ≤ i < R_j. Важно: строка считается активной, если i находится строго внутри интервала, не включая правую границу R_j. Это связано с тем, что на правой границе строка "заканчивается" и её вклад больше не учитывается.

Количество активных строк A_i определяет число узлов на ярусе i: число узлов = 2^{A_i}.

### Профиль сложности решётки

Профиль сложности — это вектор, показывающий число узлов на каждом ярусе от 0 до n. Для примера выше профиль будет:
- ярус 0: A₀=0 → 1 узел
- ярус 1: A₁=1 (активна строка 1) → 2 узла
- ярус 2: A₂=2 (активны строки 1 и 2) → 4 узла
- ярус 3: A₃=3 (активны все три строки) → 8 узлов
- ярус 4: A₄=2 (активны строки 2 и 3, строка 1 закончилась) → 4 узла
- ярус 5: A₅=1 (активна строка 3) → 2 узла
- ярус 6: A₆=0 → 1 узел

Профиль: [1, 2, 4, 8, 4, 2, 1].

### Построение рёбер

Рёбра между ярусами i-1 и i строятся следующим образом:

1. Каждый узел на ярусе i-1 соответствует конкретным значениям информационных битов, относящихся к активным на этом ярусе строкам. Узел кодируется вектором этих значений.

2. Для каждого такого узла рассматриваются два возможных перехода — соответствующие добавлению нового бита (0 или 1) на следующем ярусе. Но фактически кодовый символ на позиции i вычисляется как XOR всех активных элементов i-го столбца, умноженных на соответствующие информационные биты текущего узла.

3. Из каждого узла выходит ровно два ребра (для двоичного кода), помеченные 0 и 1, но они ведут в разные узлы следующего яруса. Новый узел на ярусе i определяется добавлением нового бита в вектор активных состояний.

4. Если два разных пути на ярусе i приходят в один и тот же узел (имеют одинаковый вектор активных состояний), они "схлопываются" — это естественное свойство решётки, обеспечивающее её минимальность.

### Визуализация решётки

Для приведённого примера решётка имеет симметричную структуру:

Ярус 0: [1 узел]
        ↓
Ярус 1: [2 узла] ←── рёбра с символами 0 и 1
        ↓
Ярус 2: [4 узла]
        ↓
Ярус 3: [8 узлов]  ← максимум разветвлений
        ↓
Ярус 4: [4 узла]   ← начало схлопывания
        ↓
Ярус 5: [2 узла]
        ↓
Ярус 6: [1 узел]

Такая структура характерна для многих линейных кодов.

## 4. Алгоритм Витерби

Алгоритм Витерби — это метод динамического программирования для поиска наиболее вероятного пути в решётке. Он используется для декодирования по максимуму правдоподобия (MLD).

### Основная идея

Вместо того чтобы перебирать все 2^k путей (что невозможно при больших k), алгоритм проходит по решётке ярус за ярусом, на каждом этапе отбрасывая заведомо неоптимальные пути. Отбрасывание происходит на основе сравнения метрик путей, приходящих в один и тот же узел.

### Пошаговое описание алгоритма

**Шаг 1. Инициализация**
- Начальному узлу (ярус 0) присваивается метрика 0.
- Всем остальным узлам присваивается метрика ∞ (или очень большое число).
- Для каждого узла запоминается "выживший" путь, ведущий в него.

**Шаг 2. Прямой проход (для каждого яруса i от 1 до n)**
- Для каждого узла на текущем ярусе i рассматриваются все входящие в него рёбра (обычно 2 ребра из двух разных узлов предыдущего яруса).
- Для каждого входящего ребра вычисляется кандидатная метрика:
  M_канд = M(узел на i-1) + метрика_ребра
- Из всех кандидатов выбирается минимальный — это и будет новая метрика для данного узла на ярусе i.
- Выбранный путь запоминается как "выживший" (survivor path).
- Остальные пути, ведущие в этот же узел, отбрасываются.

**Шаг 3. Метрики рёбер**
- При жёстком декодировании (символы 0/1) метрика ребра равна 0, если принятый символ совпадает с меткой ребра, и 1 — если не совпадает (расстояние Хэмминга).
- При мягком декодировании (вещественные значения из канала) метрика вычисляется как квадрат разности между принятым значением и идеальным значением символа (например, +1 для 1 и -1 для 0).

**Шаг 4. Терминация**
- После обработки последнего яруса n выбирается узел с минимальной накопленной метрикой.
- Соответствующий путь является наиболее вероятным кодовым словом.

**Шаг 5. Обратный проход (traceback)**
- Начиная с выбранного конечного узла, двигаемся назад по запомненным выжившим путям.
- На каждом шаге восстанавливаем символ, соответствующий пройденному ребру.
- В результате получаем декодированное кодовое слово.

### Сложность алгоритма

Вычислительная сложность алгоритма Витерби пропорциональна общему числу рёбер в решётке:
- на каждом ярусе i число рёбер = число узлов на i-1 × 2 (для двоичного кода);
- общая сложность ≈ сумма числа рёбер по всем ярусам.

Для большинства кодов это значительно меньше, чем 2^k. Например, для кода (8,4) сложность порядка нескольких десятков операций, а не 16 сравнений.

### Преимущества алгоритма Витерби

1. Гарантирует оптимальное декодирование по максимуму правдоподобия.
2. Работает как с жёсткими, так и с мягкими решениями из канала.
3. Имеет фиксированную сложность, не зависящую от количества ошибок.
4. Хорошо подходит для аппаратной реализации (конвейерная обработка).

### Практические замечания

- Для очень длинных кодов (n > 1000) память для хранения выживших путей может стать проблемой. Обычно используют фиксированную глубину traceback (например, 5×длина кода).
- В реальных системах алгоритм Витерби применяется не только для блоковых кодов, но и для свёрточных кодов, где он был впервые предложен.

## 5. Связь MSF и решётки

Минимальная спэновая форма гарантирует, что построенная по ней решётка будет иметь наименьшее возможное число узлов для данного кода. Это достигается за счёт того, что в MSF:

- число активных строк на каждом ярусе минимально;
- переходы между состояниями организованы наиболее компактно;
- исключены избыточные состояния, которые могли бы появиться при другом базисе.

Без MSF можно построить решётку, но она будет содержать лишние узлы и рёбра, что увеличит сложность декодирования без всякой пользы.

## 6. Заключение

В лекции рассмотрены ключевые понятия, необходимые для эффективного декодирования линейных блоковых кодов:

- минимальная спэновая форма порождающей матрицы как способ компактного представления кода;
- построение минимальной решётки на основе MSF с определением активных строк и профиля сложности;
- алгоритм Витерби как метод оптимального декодирования с использованием решётки.

Эти инструменты позволяют перейти от теоретического описания кодов к их практической реализации в системах передачи данных с помехами.
